The two app specs need helpers that the skeleton-core spec does not define yet. Amend the skeleton-core spec in place (edit the three existing files, do not create new spec folders) with the following additions, keeping the existing numbering and style and adding new requirement numbers at the end:

REQ-10 Page composition (new module skeleton/src/builder.ts). A PageBuilder that apps use to lay out pages without writing raw bytes. Operations: header(pageNumber, serviceName, clockText) for row 0; title(text) for rows 1 and 2 (double height, cyan); text(row, col, str, options) with options for foreground colour, background colour and a hard cap at column 39 (text that does not fit is truncated with a visible marker, never wrapped into another row); heading(row, str) in yellow; value(row, col, str) in white; mosaicBar(row, col, width, fraction, colour) that draws a horizontal bar with G1 mosaic blocks using the mosaic helpers; list rows with a right-aligned value; wrapText(str, width) returning lines; and build() returning a RawPage. The builder must place each colour or size control code in its own cell (control codes occupy a cell, per the reference), must never write outside row and column bounds, and must never put data text on row 23.
  [PBT] criteria: any sequence of builder operations yields a page of exactly 960 bytes with every byte in 0 to 127; text never overwrites row 23; mosaicBar with any fraction between 0 and 1 uses a number of filled blocks that is monotonic in the fraction; wrapText lines never exceed the width and rejoin to the original words.

REQ-11 Page providers and the viewer. Define a PageProvider type: (pageNumber: number, subpage: number) => Promise<ProvidedPage | null> where ProvidedPage has subpages (RawPage array) and a FastextConfig. Define a mountTeletext(element, provider, options) function in viewer.ts that shows a loading page while a provider call is pending, shows a not-found page for null, shows an error page when the provider rejects, and otherwise renders the page through the existing interpreter and SVG renderer. The viewer shows the typed digits in the header while a three-digit entry is in progress.
  [PBT] criteria: for any provider result the viewer state machine ends in exactly one of loading, page, not-found or error; digit entry combined with the provider never requests a page outside 100 to 899.

REQ-12 Built-in system pages. The skeleton provides makeNotFoundPage(pageNumber), makeErrorPage(title, message, fastext) and makeLoadingPage(pageNumber) so every app shows the same system screens. Messages wrap with wrapText.
  [PBT] criteria: system pages are always 960 bytes with row 23 reserved for the prompt row.
