Apps may only import the public API of the skeleton package (@skeletext/core). No code in this step.

1. .kiro/specs/repo-desk/ for apps/repo-desk, a static browser app that shows the public status of a GitHub repository as teletext pages. Data: the unauthenticated GitHub REST API (CORS is open, 60 requests per hour per IP, so every response is cached in localStorage for 5 minutes and pages fetch lazily only when opened). The repo is chosen with the query parameter ?repo=owner/name and defaults to rishabhcli/skeletext. Pages: 100 index (repo name in double height, description, stars, forks, open issues, language, license, last push age); 110 latest commits (short sha, date, author, first line of message) with two subpages; 120 open pull requests; 130 open issues; 140 GitHub Actions runs, with success in green, failure in red and in-progress in yellow; 150 language breakdown as mosaic bars; 199 about. A rate limit response (HTTP 403 or 429) shows an error page with the reset time from the X-RateLimit-Reset header. An invalid repo parameter shows an error page. Fastext: red 100, green 110, yellow 140, cyan 150. Every fetch has an 8 second timeout.

2. .kiro/specs/teletext-mcp/ for tools/teletext-mcp, a small MCP server over stdio that lets Kiro inspect teletext pages while it builds them. Tools: explain_code (byte to name and timing from the reference table), render_page (takes an encoded page or an array of 24 strings with an escape syntax for control codes, returns a text drawing of the 24 by 40 grid plus the display attributes per row), validate_page (reports rule violations such as double height on row 23, a Start Box on a normal page, a row longer than 40 cells, or bytes above 0x7F) and encode_rows (turns the same array of strings into the compact encoded form). The server reuses the skeleton interpreter and codec. Choose between the official TypeScript SDK and a minimal hand-written JSON-RPC 2.0 stdio loop and justify the choice in design.md. Include [PBT] requirements such as: encode_rows output decodes back to the same rows; validate_page never throws for any input string; render_page output always has exactly 24 lines of 40 visible columns.
